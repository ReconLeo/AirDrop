# AirDrop 插件更新规划（适配 FlaskToolkit v4.17.1）

> 基线：当前 AirDrop 仓库 `v1.0.0` tag 对应的插件（`plugin/`）
> 目标框架：FlaskToolkit v4.17.1（2026-09-11 release runtime）
> 参考规范：`Flask-Plugin-Framework-Dev-Guide-v4.md`（v4.17 全文）

---

## 1. 现状与验证结论（2026-09-11，干净 runtime 实测）

将当前 `plugin/` 复制进 FlaskToolkit **v4.17.1 runtime**（GitHub release 精简包）加载实测：

| 项 | 结果 |
|---|---|
| 插件类加载 | ✅ `airdrop` 出现在 `global_var.plugins` |
| 9 条路由注册 | ✅ `_wrapped_routes` 9 条 |
| `/api/airdrop/test` | ✅ 200 |
| `/api/airdrop/network-addresses` | ✅ 200 |
| `/api/airdrop/files` | ✅ 200（沙箱拦截 os.remove 清理过期，接口仍 200） |
| `/plugin/airdrop` 页面 | ✅ 200 |
| **`plugins/airdrop.json` 描述文件** | ❌ **非法 JSON**，框架 `读取插件描述文件失败，忽略` |

**结论**：插件类与核心 API 在 v4.17 下**基本兼容**（`success_response`/`error_response`/`save_uploaded_file`/`send_file_response`/`check_upload`/移动端能力均在）。用户所述"已不能正常加载"的根因是 **`airdrop.json` 非法导致描述文件被框架忽略**，进而版本/`capabilities`/`require_framework_version` 全部丢失，不符合 v4.17 插件规范。

## 2. 不合规点清单（对照 v4.17 规范）

| # | 问题 | 规范依据 | 影响 |
|---|------|----------|------|
| 1 | **`airdrop.json` 非法 JSON**（第 9 行 `"require_framework_version": "4.2.2"  # 注释`，JSON 不允许注释） | 5.6 插件包描述文件 | 描述文件被忽略，版本/描述/capabilities/require 全丢；上传/更新会被描述一致性校验拒绝 |
| 2 | **缺 `capabilities` 能力声明** | 10.7 Deny by Default | `PLUGIN_SCAN_MODE=enforce` 下安装被拒；report 模式附缺失清单 |
| 3 | **未插件包化**（无 `manifest.json` 完整性清单、无 `.zip` 分发形态） | 5.6 / 10.5 | 不符合分发规范；`PACKAGE_INTEGRITY_MODE=strict` 拒绝 |
| 4 | **未充分利用 BasePlugin 能力**（手写上传双层校验/下载，未用 `save_uploaded_file`/`send_file_response`/`check_upload`） | 5.4.2 / 10.10 | 代码冗余；缺配额预检/中文名 Range/下载统计等框架能力 |
| 5 | `require_framework_version` 因 json 非法失效 | 5.7 | 应明确声明适配版本（至少覆盖所用 API，如 `4.2.2`；若用 v4.17 能力则 `4.17.0`） |
| 6 | 可选：缺移动端模板（v4.17）/ i18n（v4.9） | 5.10 / 15 | 移动端回退桌面模板可用，但未利用 v4.17 移动端分发 |

## 3. 更新目标

按 v4.17 规范将 AirDrop 插件从"可运行但不合规"升级为**规范合规、可分发、可签名、可安装**的插件包：

- ✅ 描述文件合法、描述一致性对齐（`airdrop.json` ↔ 类属性）
- ✅ `capabilities` 声明齐全（Deny by Default 合规）
- ✅ 复用 BasePlugin 传输/配额能力，精简代码
- ✅ 插件包化 + `manifest.json` 完整性 + 可选 RSA 签名
- ✅ 保留双模式鉴权（`auth_required`/`public_page`）与免登录默认
- 🎯 可选：移动端模板 / i18n

## 4. 分阶段更新计划

### Phase A · 合规最小修复（低风险）
- [ ] 修复 `plugin/airdrop.json` 为合法 JSON（去 `#` 注释），补 `require_framework_version`、`capabilities`
- [ ] 描述一致性核对：`airdrop.json` ↔ `AirDropPlugin` 类属性（version/title/author/permission/category/description 一致，`name` 三处一致）
- [ ] 在 v4.17 runtime 复测：描述文件被正确读取、catalog 显示正确版本/capabilities

### Phase B · 复用 BasePlugin 能力（重构）
- [ ] 上传：用 `save_uploaded_file`（自动大小预检 + 类型校验）+ `check_upload`（存储配额预检）替代手写双层校验
- [ ] 下载：用 `send_file_response`（中文名 RFC 5987 + Range + 下载统计）替代 `send_from_directory`
- [ ] 存储目录：接入插件数据目录 `self.get_data_path()` / 声明 `storage:limit` 配额（替代配置绝对路径？保留 `upload_folder` 兼容）
- [ ] 回归：上传/下载/批量/过期清理全链路

### Phase C · 插件包化 + 签名 + 发布（分发合规）
- [ ] 整理插件包源目录（`plugin.json` + `airdrop.py` + `templates/` + `static/`）
- [ ] `python tools/package.py pack` 生成 `.zip` + `manifest.json`（`--sign` 可选签名）
- [ ] `python tools/scan.py` 静态扫描自检（确认无高风险行为或已声明）
- [ ] `python tools/install_plugin.py backend airdrop.zip` 离线安装验证
- [ ] 发布：更新 `plugin/airdrop.json`、`plugin/airdrop.py` 版本号 → 打 tag v1.1.0 / v2.0.0

### Phase D · 增强（可选）
- [ ] 移动端独立模板 `templates/plugins/airdrop/mobile/`（v4.17 命名空间）
- [ ] i18n 语言包（插件词条随框架语言切换）

## 5. capabilities 声明建议（依据代码实际行为）

`plugin/airdrop.json` 需声明（`PLUGIN_SCAN_MODE=enforce` 合规）：

```json
"capabilities": [
    "filesystem:read:uploads",        // 下载/列表读上传目录
    "filesystem:write:uploads",       // 上传写/删除 os.remove/过期清理
    "network:udp:10.254.254.254",     // get_lan_addresses UDP 探测本机 IP
    "process:exec:explorer",          // open_upload_folder 打开文件夹（Windows）
    "process:exec:ipconfig",          // get_lan_addresses 取局域网 IP（Windows）
    "process:exec:hostname",          // get_lan_addresses 兜底（Linux/macOS）
    "scheduler"                       // scheduled_tasks 过期清理定时任务
]
```

> 注意：`upload_folder` 当前为绝对路径（`H:/Coding/Projects/AirDrop/uploads`），capabilities 路径声明需与之一致（绝对或改相对项目根）。Phase B 建议统一存储目录策略后确定。

## 6. 验证方式

- 干净 runtime（v4.17.1 release）加载 + 全接口/页面回归（复用本仓库 `tests/test_airdrop_loader.py`，扩展描述文件/capabilities 断言）
- `python tools/scan.py` 静态扫描无未声明高风险
- `python tools/install_plugin.py` 离线安装/卸载闭环
- 双模式鉴权回归（免登录 / auth 插件安装后权限矩阵）

## 7. 风险与注意

- `get_lan_addresses` 的 `socket`/`subprocess`/`os.remove` 属静态扫描中/高危项，务必在 `capabilities` 显式声明，否则 `enforce` 拒绝。
- `upload_folder` 绝对路径与 capabilities 匹配、及 `storage:limit` 配额衔接需在 Phase B 统一决策。
- 插件包化后仓库内 `plugin/` 形态与发布 `.zip` 需保持同步（源目录 + 打包产物）。
