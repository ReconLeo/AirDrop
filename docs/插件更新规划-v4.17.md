# AirDrop 插件更新规划（适配 FlaskToolkit v4.17.1）

> 基线：当前 AirDrop 仓库 `v1.0.0` tag 对应的插件（`plugin/`）
> 目标框架：FlaskToolkit v4.17.1（2026-09-11 release runtime）
> 参考规范：`Flask-Plugin-Framework-Dev-Guide-v4.md`（v4.17 全文）

---

## 1. 现状与验证结论（2026-09-11，干净 runtime 实测）

将当前 `plugin/` 复制进 FlaskToolkit **v4.17.1 runtime**（GitHub release 精简包）加载实测：

| 项 | 结果 |
|---|---|
| 插件类加载 | ✅ `airdrop` 出现在 `global_var.plugins` |
| 9 条路由注册 | ✅ `_wrapped_routes` 9 条 |
| `/api/airdrop/test` | ✅ 200 |
| `/api/airdrop/network-addresses` | ✅ 200 |
| `/api/airdrop/files` | ✅ 200（沙箱拦截 os.remove 清理过期，接口仍 200） |
| `/plugin/airdrop` 页面 | ✅ 200 |
| **`plugins/airdrop.json` 描述文件** | ❌ **非法 JSON**，框架 `读取插件描述文件失败，忽略` |

**结论**：插件类与核心 API 在 v4.17 下**基本兼容**（`success_response`/`error_response`/`save_uploaded_file`/`send_file_response`/`check_upload`/移动端能力均在）。用户所述"已不能正常加载"的根因是 **`airdrop.json` 非法导致描述文件被框架忽略**，进而版本/`capabilities`/`require_framework_version` 全部丢失，不符合 v4.17 插件规范。

## 2. 不合规点清单（对照 v4.17 规范）

## 3. 更新目标

按 v4.17 规范将 AirDrop 插件从"可运行但不合规"升级为**规范合规、可分发、可签名、可安装**的插件包：

- ✅ 描述文件合法、描述一致性对齐（`airdrop.json` ↔ 类属性）
- ✅ `capabilities` 声明齐全（Deny by Default 合规）
- ✅ 复用 BasePlugin 传输/配额能力，精简代码
- ✅ 插件包化 + `manifest.json` 完整性 + 可选 RSA 签名
- ✅ 保留双模式鉴权（`auth_required`/`public_page`）与免登录默认
- 🎯 可选：移动端模板 / i18n

## 5. capabilities 声明建议（依据代码实际行为）

`plugin/airdrop.json` 需声明（`PLUGIN_SCAN_MODE=enforce` 合规）：

```json
"capabilities": [
    "filesystem:read:uploads",        // 下载/列表读上传目录
    "filesystem:write:uploads",       // 上传写/删除 os.remove/过期清理
    "network:udp:10.254.254.254",     // get_lan_addresses UDP 探测本机 IP
    "process:exec:explorer",          // open_upload_folder 打开文件夹（Windows）
    "process:exec:ipconfig",          // get_lan_addresses 取局域网 IP（Windows）
    "process:exec:hostname",          // get_lan_addresses 兜底（Linux/macOS）
    "scheduler"                       // scheduled_tasks 过期清理定时任务
]
```

> 注意：`upload_folder` 当前为绝对路径（`H:/Coding/Projects/AirDrop/uploads`），capabilities 路径声明需与之一致（绝对或改相对项目根）。Phase B 建议统一存储目录策略后确定。

## 7. 风险与注意

- `get_lan_addresses` 的 `socket`/`subprocess`/`os.remove` 属静态扫描中/高危项，务必在 `capabilities` 显式声明，否则 `enforce` 拒绝。
- `upload_folder` 绝对路径与 capabilities 匹配、及 `storage:limit` 配额衔接需在 Phase B 统一决策。
- 插件包化后仓库内 `plugin/` 形态与发布 `.zip` 需保持同步（源目录 + 打包产物）。

## 8. 严格模式合规（enforce，用户要求 2026-09-11）

### 8.1 验证标准
采用框架**严格模式**作为插件规范性的最高验证标准（`profile strict` / `PLUGIN_SCAN_MODE=enforce` + `PACKAGE_INTEGRITY_MODE=strict` + `AUDIT_HOOK_MODE=enforce`）：**enforce 下检出高风险（high>0）或 capabilities 未声明行为（missing）即拒绝安装**。

### 8.2 当前静态扫描结果（`tools/scan.py plugins/airdrop.py` 实测）

```
high=6  medium=6  low=0  info=1
HIGH : import subprocess；启动子进程 ×5（open_upload_folder explorer、get_lan_addresses ipconfig/hostname）
MED  : import socket；创建网络套接字；os.remove 删除文件 ×4
INFO : open 文件读取
范围-网络: tcp://10.254.254.254
```

**结论**：当前 `airdrop.py` 在 enforce 下会被拒绝安装（high=6）。

### 8.3 高风险消除方案（使插件通过 enforce）

| 高风险来源 | 消除方案 | 效果 |
|---|---|---|
| `get_lan_addresses()`（subprocess ipconfig/hostname + socket 探测，约 60 行） | 复用框架 `core.network.get_lan_addresses()`（同源官方实现），删除手写代码 + `import subprocess/socket` | 消除 5 项 high + 2 项 medium |
| `open_upload_folder()`（subprocess.Popen explorer） | **Windows** 改用 `os.startfile()`（不在扫描器危险调用列表，非 high）；**macOS/Linux** 见决策点 | 消除 subprocess 剩余 high |
| `os.remove` 删除文件（上传超限/删除/批量/过期清理） | 保留但**显式声明** `filesystem:write:uploads`（medium 非 high，声明即合规） | missing 消除 |
| `scheduled_tasks` 定时任务 | 声明 `scheduler` | missing 消除 |

### 8.4 达到严格模式合规后的 capabilities 声明（enforce 通过）

```json
"capabilities": [
    "filesystem:read:uploads",
    "filesystem:write:uploads",
    "network:udp:10.254.254.254",
    "process:exec:explorer",     // 若 open_upload_folder 保留 subprocess（跨平台方案 B）
    "scheduler"
]
```

### 8.5 决策点：open_upload_folder 跨平台 vs 严格模式合规

| 方案 | 行为 | 严格模式 |
|---|---|---|
| **A（推荐）** | Windows 用 `os.startfile()`；macOS/Linux 返回"不支持打开"降级提示 | ✅ 达成 enforce 合规 |
| **B** | 保留跨平台 subprocess（macOS `open` / Linux `xdg-open`） | ❌ 仍含 high，仅 report 模式可用 |

> 说明：`open_upload_folder` 是"服务端打开上传目录"功能，实际使用场景几乎都在 Windows 桌面服务端；方案 A 以 `os.startfile` 满足严格模式，代价是 macOS/Linux 上该功能降级。
